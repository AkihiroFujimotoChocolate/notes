# メモ登録API v1 テスト仕様書

## 1. 対象・適用範囲

### 1.1 対象と目的

メモ登録API v1の外部・内部契約への適合を確認する。

### 1.2 試験対象の境界

- 外部テスト：HTTP受付と登録の通常経路を対象とし、保存実装を代役にする。
- 内部テスト：登録処理の直接呼出しと本番DI登録を対象とする。

実際の永続化は[仕様・テスト対応表](specification-test-mapping.md)に記載する別の確認で扱う。

## 2. 共通条件

### 2.1 試験環境と共通設定

#### 2.1.1 試験環境

| 試験方式 | 準備 |
|---|---|
| 外部HTTP試験 | 本番のHTTPエントリーポイントをテストホストで起動し、`INoteStore`を試験用保存実装に置き換える |
| 登録処理の直接試験 | `NoteRegistration`を試験用`INoteStore`と共に生成 |
| DI構成の試験 | 本番DI登録から要求スコープを生成 |

各条件で新しいホストまたは対象を用意する。

#### 2.1.2 共通設定

外部設定なし。

#### 2.1.3 試験側の時間制限

HTTP送信、非同期呼出し、ホスト停止は各10秒を上限とする。

### 2.2 入力と代役の条件・期待結果

#### 2.2.1 入力

| JSON項目・引数 | 値 |
|---|---|
| `title` | `"買い物"` |
| `content` | `"牛乳"` |

外部HTTP試験のContent-Typeは`application/json`。直接試験の`cancellationToken`は通常`CancellationToken.None`、取消試験では取消可能なトークンとする。

#### 2.2.2 保存代役

| 条件 | 動作 |
|---|---|
| 通常 | `Note`と取消トークンを呼出しごとに記録し、指定されたboolを返す。既定値は`true` |
| 取消試験 | 引数を記録して呼出し到達を通知し、受け取ったトークンの取消まで待機する。取消時に`OperationCanceledException`を発生させる |

### 2.3 観測と判定

#### 2.3.1 HTTP応答

HTTP応答が返った後に応答と保存代役の記録を確認する。JSONはデコード後の型と値を比較する。

| 条件 | 期待するHTTPステータス | JSON項目・期待結果 |
|---|---:|---|
| 保存成功 | 201 | `id`：string、UUIDとして解釈でき、保存記録の`Note.Id`と同じUUID |
| 入力エラー | 400 | `error`：string、`"invalid_input"` |
| 保存失敗 | 503 | `error`：string、`"storage_unavailable"` |

#### 2.3.2 内部境界

| 観測対象 | 判定方法 |
|---|---|
| 保存代役の記録 | 引数と呼出し回数を3章の条件に従って比較 |
| 登録結果 | `Saved`と`Id`を比較 |
| 取消 | 呼出し元と代役が受け取ったトークンの同一性、取消例外を確認 |
| DI | 解決したインスタンスの参照同一性を比較 |
| 宣言 | 公開コンストラクターの引数型を確認 |

### 2.4 共通実行手順

1. 各条件で代役と対象を初期化し、ホストまたはスコープを用意する。
2. ケースに従って入力を送信または対象を呼び出す。
3. 応答・結果・記録を取得して判定する。
4. 使用したホスト・スコープを停止または破棄する。

### 2.5 診断記録と再現方法

#### 2.5.1 実行前の記録

| 分類 | 記録する内容 |
|---|---|
| 実行前 | ケースID、条件ID、入力、代役の結果・取消条件 |
| 失敗時 | 実際の応答または戻り値、保存代役の記録、例外またはDI解決結果 |

#### 2.5.2 再現方法

記録した入力と代役の設定を使って同じ条件を再実行する。

# 外部仕様書

## 1. 役割

サービスが受ける要求と返す応答、サービス自身が開始する呼出し、外部から観測できる処理規則を定める。接続先が同一システム内であっても、誰が要求を開始するかで提供・利用インターフェースを分類する。

## 2. 推奨章構成

| 章 | 記載内容 |
|---|---|
| 1. 対象・適用範囲 | 対象サービス、版、提供する機能。 |
| 2. 用語・前提 | 用語と動作の前提。 |
| 3. 提供インターフェース | 呼出しを受ける際の要求・検証・応答。 小節：接続条件、要求、検証、応答。 |
| 4. 利用インターフェース | 他のサービスを呼び出す際の要求・応答・認証。 小節：接続一覧、要求、応答、認証。 |
| 5. 処理規則 | インターフェース間の対応と処理順序。 小節：全体フロー、対象の選別、入出力の対応、応答と後続処理。 |
| 6. エラー・タイムアウト | 異常時の結果と処理期限。 小節：受付時の異常、呼出し結果の扱い、期限と復帰。 |
| 7. 設定 | 設定項目と動作。 小節：設定項目と動作、設定と通信値の区別。 |
| 8. 参照資料 | 根拠資料と契約の適用版。 小節：プロジェクト資料、接続先の実装資料、外部公式ドキュメント。 |

## 3. インターフェース

接続条件には呼出し元または呼出し先、用途、HTTPメソッド、パス、メディアタイプ、ヘッダー、認証を記す。要求・応答は方向を明示し、JSON本文は項目・型・値／条件の表を使う。

| 項目 | 型 | 条件・値 |
|---|---|---|
| `request_id` | string | 必須。呼出し元の要求ID |
| `items` | object[] | 必須。1件以上 |
| `items[].text` | string | 各要素で必須。入力本文 |

配列の件数、項目の省略・null・空文字・空白文字の扱いは契約上必要な範囲で定める。JSON例は表の補助として使用する。固定値、転記元、合成方法、型を特定する。

## 4. 条件と処理順序

悪い例：「有効な場合は処理する。それ以外は無視する。」

改善例：

| 対象 | 条件 | 結果 |
|---|---|---|
| 各入力項目 | `type` が `"text"` | 本文を後続サービスへ1回送信 |
| 各入力項目 | `type` が `"text"` 以外 | 当該項目の後続送信0回 |

適用対象と条件を明記する。HTTP受付の結果、後続処理の結果、利用者への通知をそれぞれ記述する。非同期処理は応答がいつ返るかと後続処理が開始・完了する条件を示す。図は必要な場合に本文と整合する概念図を置く。

## 5. 値の取得元・ID・設定

| 項目 | 記載例 |
|---|---|
| 固定値 | `"note"` |
| 合成値 | `"user-"` + 要求の `user_id` |
| 転記 | 要求本文の `content` |
| ID | 受付成功後にUUIDを生成し、当該処理の保存・応答で同じ値を使う |
| 設定 | `Storage:Endpoint` を起動時に読み取る |

設定キー、型、値、既定値、優先順位、読込時点、変更の反映時点を必要な範囲で定める。「未指定」がキーの不在を指すのか空文字を含むのかを明確にする。通信で受け取る値と設定値を区別する。秘密値は実値を載せず取得元を示す。

## 6. エラーと期限

異常の発生条件と外部結果を対応させる。HTTPステータス、本文、送信回数、再試行、後続処理、処理期限、取消後の動作など、採用する契約を記す。正常形式の採用条件と失敗時の動作を別々に曖昧な注意文で繰り返さない。未規定の異常を追加の合否条件にしない。

### 6.1 記述の粒度

処理終了が規定されている場合は、その分岐で返す応答と終了を示す。終了分岐と同じ内容を後続要求0件という説明で重複させない。外部の観測上保証する件数や再試行回数が契約なら、その規定は残す。

接続先ごとの要求・応答は、用途、項目、型、送信値、受信値の意味を区別する。必須・任意が混在する場合は「必須」列を設ける方法が使える。接続一覧、対象選別、エラー、設定、参照資料を含む表の具体例は[外部仕様の記述例](writing-examples/external-specifications.md)を参照する。

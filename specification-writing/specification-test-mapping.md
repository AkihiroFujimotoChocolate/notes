# 仕様・テスト対応表

## 1. 目的

仕様条項ごとに確認方法と参照先を明示し、確認漏れ、重複、試験とレビューの分担を把握する。対応表は実行結果の記録とは区別する。

## 2. 推奨構成

| 章 | 内容 |
|---|---|
| 1. 対象・参照資料 | 対象、版、参照した仕様とテスト仕様。 |
| 2. 外部仕様との対応 | 外部仕様の条項順に記載。 |
| 3. 内部仕様との対応 | 内部仕様の条項順に記載。 |

同じサービス・版について外部仕様・内部仕様の対応を一つにまとめられる。版非依存の契約は適用範囲を示す。統合型の仕様でも外部と内部の確認を区別できる。

## 3. 記述方法

| 仕様書の条項 | 規定内容 | 対応する節・テストケース |
|---|---|---|
| 3.4 | 正常応答201 | 外部-01（自動） |
| 3.3 | 空文字拒否 | 外部-02（自動） |
| 内部3.3 | 依存方向 | 内部-01（自動）＋本体レビュー |
| 6.3 | 障害後の復旧 | 手動確認手順への参照 |
| 7.1 | 設定切替 | 一部対応：通常設定のみ。変更後の確認は未対応 |

条項順に記載し、ケースと該当箇所へリンクする。共通条件、部分対応、未対応、後続作業も記載する。仕様の条項に含まれる複数条件の一部だけを確認する場合は、未確認の内容を明示する。

## 4. 確認方法の選択

自動化の複雑さに対して得られる保証が小さい場合、コードレビューや手動試験を用いる。構造の確認では、宣言やコンパイル済み依存を自動検査し、委譲先や制御の意味はレビューするなど補完できる。判定方法のない期待結果を自動試験の代用にしない。実行した結果や証跡は作業記録へ置く。

# 外部仕様の記述例

各表は架空の独立した契約の記述例。[完成サンプル](../examples/external-specification.md)とは別の例も含む。

## 1. 用語・前提

| 用語 | 意味 |
|---|---|
| メモ | タイトルと本文を持つ登録対象 |
| 登録ID | 登録ごとに生成する識別子 |

## 2. 接続条件

| 項目 | 仕様 |
|---|---|
| HTTPメソッド | POST |
| パス | `/notes` |
| Content-Type | `application/json` |
| 認証 | Bearerトークン |

要求本文は[3.1](#31-要求)の表に記載する。

## 3. 提供インターフェース

### 3.1 要求

| 項目 | 型 | 必須 | 値・意味 |
|---|---|---|---|
| `title` | string | はい | 空文字以外のタイトル |
| `content` | string | はい | 本文。空文字可 |
| `tags` | string[] | いいえ | 0件以上。省略時は空配列 |

全項目の必須条件が同じ場合は、必須列を省略して表の条件欄または共通条件で示せる。省略、null、空文字は契約で区別する。

### 3.2 応答

| 条件 | HTTPステータス | JSON本文 |
|---|---:|---|
| 保存成功 | 201 | `id`（登録ID） |
| 入力エラー | 400 | `error`（`"invalid_input"`） |

応答の本文が複雑なら、条件・ステータスの表と本文項目の表を分ける。

## 4. 利用インターフェース

### 4.1 接続一覧

| 呼出し先 | 用途 | メソッド・送信先 |
|---|---|---|
| 保存API | メモの保存 | POST `https://storage.example/notes` |
| 通知API | 保存完了の通知 | POST `https://notify.example/events` |

### 4.2 要求

#### 4.2.1 保存API

| 項目 | 型 | 送信する値 |
|---|---|---|
| `request_id` | string | 登録時に生成したUUID |
| `title` | string | 受信した要求の `title` |
| `category` | string | `"note"` |
| `owner_id` | string | `"user-"` + 認証済み利用者ID |

値を「適切な値」「対応する値」とだけ書かず、取得元・固定値・合成方法を特定する。複数の接続先は対象名の節で区分する。

### 4.3 応答

#### 4.3.1 保存API

| 項目 | 型 | 意味 |
|---|---|---|
| `id` | string | 保存されたメモの識別子 |
| `created_at` | string | UTCの作成日時（RFC 3339形式） |

送信要求は送信側が組み立てる値、受信応答は受信項目の意味と判定に必要な条件を示す。

## 5. 処理規則

### 5.1 対象の選別

| 項目 | 処理対象とする条件 |
|---|---|
| `type` | `"note"` |
| `owner_id` | 認証済み利用者IDと一致 |

例：すべての条件が成立した項目を保存対象とし、他の項目は処理を終了する。条件がANDかORか、対象単位は何かが表から定まらなければ明記する。

### 5.2 処理順序

1. 入力を検証する。
2. 検証成功後、登録ごとにUUIDを生成する。
3. 保存APIに要求を送る。
4. 保存成功の場合、保存結果を応答に設定する。

入力の内容が同じかどうかを調べるロジックがなければ、「入力が同じ場合でも」という条件を付けない。

## 6. エラー・設定・参照資料

### 6.1 エラー

| 条件 | 動作 |
|---|---|
| 入力検証失敗 | HTTP 400を返して処理終了 |
| 保存APIがHTTP 503を返す | HTTP 503を返して処理終了 |

終了によって後続処理が行われないことが定まる場合、同じ内容を件数として再記載しない。外部契約として回数を定める場合は記載する。

### 6.2 設定

| 設定キー | 値・動作 |
|---|---|
| `Storage:Endpoint` | 指定されたURLを保存APIの送信先とする |
| `App:BaseUrl` | `Storage:Endpoint`が未指定の場合、末尾に `/storage` を付けて送信先とする |

この例の未指定はキーが存在しないことを指す。空文字の扱いは実際の契約に従う。必要な型、既定値、読込時点を表の列または該当行に記載する。
